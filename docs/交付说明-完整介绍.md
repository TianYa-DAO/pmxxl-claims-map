# 交付说明：领地小地图（插件 + 模组）完整介绍

## 一、总览

1. 本交付由两个可运行件组成，分别跑在服务端和客户端：
   服务端插件 PmxxlClaims-plugin-1.0.0.jar（28,556 字节，放 plugins/）
   客户端模组 pmxxlclaims-mod-1.0.0.jar（39,741 字节，放 .minecraft/mods/）
2. 职责边界：服务端插件只读 Residence 数据并下发，不做判定、不存数据；客户端模组只接收与渲染，不做判定、不发写操作。
3. 数据流：Residence（真数据源）→ ClaimService 查询组装 → ClaimCodec 编码 → 插件消息频道 pmxxl:claims → 客户端 ClaimCache → MinimapRenderer 绘制。
4. 兜底数据流：服务端没装插件时，客户端 AutoScanner 静默发 /res show → ChatParser 解析聊天回显 → ClaimStore 持久化 → 同样交给 MinimapRenderer 绘制。

## 二、服务端插件 PmxxlClaims

### 2.1 运行环境

1. 服务端：Purpur/Paper/Spigot 1.21.11，Java 21。
2. 编译依赖：paper-api 1.21.11-R0.1-SNAPSHOT（provided），Residence 5.1.6.2（provided）。
3. 运行依赖：Residence 5.1.6.2 及其硬依赖 CMILib，已真实环境验证。

### 2.2 类结构与职责（共 8 个类）

1. PmxxlClaims（主类）：读配置、检查 Residence、创建 ClaimService/ClaimPublisher、注册频道与监听器、注册命令，提供 service() 与 assumeClientUnregistered() 访问器，reloadPlugin() 重建服务。
2. claim/ClaimService：核心查询。按玩家所在区块生成半径内 ChunkRef 列表（默认半径 16，最多 33×33=1089 个），调 ResidenceManager.getResidences 取回领地集合，递归展开子领地，用「父链/名字」完整路径去重，逐区域转成 XZ 矩形，按 owner 哈希取 8 色板之一；内含 ChunkRef 列表缓存（上限 256）与查询结果快照缓存（按 世界|中心区块，5 秒有效、领地变更时整体失效）。
3. claim/ClaimData：协议数据模型，Area(minX,minZ,maxX,maxZ)、Claim(name,owner,color,flags,areas)，FLAG_SUBZONE 标记子领地。
4. net/ClaimCodec：PMC3 编码器。magic、"flags(bit0=Deflate)"、body（世界字符串上限 512 字节、名字/owner 上限 120 字节且按 UTF-8 字符边界截断、varint 计数、每条领地的颜色/旗标/区域列表），body 超过 1024 字节自动 Deflate。
5. publish/ClaimPublisher：下发调度。内容签名（64 位哈希）未变且未到心跳就跳过；主线程取快照后在异步线程编码，回主线程发送；每玩家递增 revision 作废旧任务；10 秒心跳必发一次；超过 1 MiB 上限时折半裁剪，警告按玩家 60 秒限频；发送失败清哈希下轮重试；只给注册了 pmxxl:claims 频道的客户端发（assume-client-unregistered 可放宽）。
6. listener/PlayerListener：玩家跨区块立即刷新、进服 2 秒后补发、换世界刷新、退出清理每玩家状态。
7. listener/ClaimChangeListener：Residence 的创建/删除/改大小/改名/换主/加区域/删区域 7 个事件统一打脏标记，下一 tick 合并刷新一次，避免批量操作卡主线程。
8. command/ClaimsMapCommand：/claimsmap reload 与 /claimsmap debug [玩家]，权限 pmxxlclaims.admin（默认 OP）。

### 2.3 配置（plugins/PmxxlClaims/config.yml）

1. radius-chunks：推送半径，单位区块，默认 16（256 格见方），允许 1~32，越界会在启动时警告并钳制。
2. send-owner：是否下发拥有者名字，默认 false（客户端当前不显示）。
3. assume-client-unregistered：仅当 BungeeCord/Velocity 代理不转发客户端频道注册时打开，默认 false。

### 2.4 设计取舍

1. 只读：不碰 Residence 代码、不存领地、不加玩家命令，Residence 升级不影响我们。
2. 主线程只取快照、编码异步：Residence 不是线程安全的，读取必须在主线程；Deflate 与序列化放在异步线程，回主线程发包。
3. 签名 + 心跳：内容不变不重复编码，但每 10 秒必须发一次，否则客户端无法区分「服务端没插件」和「数据没变化」。
4. 严格频道门控：Paper 的 getListeningPluginChannels 在真实环境已验证可用（模拟客户端注册后立即收到帧）。
5. 半径上限 32：再大会让单次查询与报文体积非线性增长，且小地图可视范围也用不到。

## 三、客户端模组 pmxxlclaims

### 3.1 运行环境

1. Fabric Loader 0.20.1、Minecraft 1.21.11、Fabric API ≥0.141.6。
2. 纯客户端模组（environment: client），不需要服务端安装任何东西。

### 3.2 类结构与职责（共 10 个类）

1. PmxxlClaimsClient（入口）：注册 payload 类型与接收器、注册 JOIN/DISCONNECT 清理、注册 M 键、每 tick 驱动 AutoScanner 与 ChatParser、挂载 HUD 元素。
2. ClaimPayload：把原始字节包装成自定义 payload，频道 id pmxxl:claims。
3. ClaimCodec：PMC3 解码器，带全字段上限（领地 ≤8192、区域 ≤512、世界 ≤512 字节、字符串 ≤256、varint 拒负数、inflate 输出 ≤4 MiB），任何异常都返回 null。
4. ClaimCache：保存最近一次推流结果（世界键 + 领地列表），收到包即标记活跃，60 秒无包自动过期。
5. ClaimStore：聊天兜底记录库，键为「服务器地址|维度|名字」，最多 2000 条、按更新时间淘汰、JSON 异步落盘、带版本号供渲染缓存失效。
6. ChatParser：解析 /res show 回显（领地行、X/Y/Z 三行或同行多组、所有者行），两角坐标配成矩形；名字判定收窄为「领地/Land/Residence」，孤立坐标行丢弃。
7. AutoScanner：兜底模式的自动查询器，按「世界|区块」记录，10 分钟 TTL，1.5 秒最小间隔，已知领地内不再查询，超过 4096 条先进先出淘汰；查询期间开 1.5 秒屏蔽窗口，只隐藏形如坐标行与随后的领地/所有者行，动作栏不动。
8. ClientConfig：config/pmxxlclaims.json 读写，7 个配置项。
9. ChunkColorCache：区块底图取色，每个区块 4×4 采样顶部方块、取地图色平均值，LRU 上限 4096 条，按维度隔离。
10. MinimapRenderer：HUD 绘制。右上角小地图（默认 128×128，1 像素 1 格，北向上），先画区块色底图，再画领地（半透明填充 + 主领地 2 像素/子领地 1 像素描边 + 色块够大时居中名字），再画玩家箭头，最后画 claims 计数；绘制列表按「世界+收包序号+本地库版本+是否活跃」缓存，scissor 用 try/finally 保证释放。

### 3.3 两种数据源与切换

1. 服务端装了插件：以推流为准，收到包后 isActive 为真，兜底自动停用。
2. 服务端没装插件：60 秒收不到包即视为无推流，自动回落到聊天兜底，AutoScanner 开始按区块静默查询。
3. 两种数据在渲染层按领地名去重合并；推流优先。

### 3.4 按键与配置（config/pmxxlclaims.json）

1. M 键开关小地图，开关状态持久化到 minimapVisible。
2. autoScan（默认 true）、intervalMs（默认 1500）、showCount（默认 true）、minimapVisible、minimapSize（默认 128，64~256）、minimapMargin（默认 6）、claimAlpha（默认 102，0~255）。

## 四、通信协议 PMC3

1. 帧结构：magic 'P','M','C','3'（4 字节）+ flags（1 字节，bit0 表示 body 经过 Deflate）+ body。
2. body：世界字符串（varint 长度 + UTF-8，≤512 字节）+ 领地数（varint）+ 每条领地（名字、owner、color int32、flags u8、区域数 varint、每区域 minX/minZ/maxX/maxZ 四个 int32）。
3. flags 的 bit0 表示子领地，渲染时描边更细。
4. 触发：玩家跨区块立即、每 3 秒巡检、领地变更合并刷新；内容签名不变时只在 10 秒心跳发送。
5. 体积实测：空包 26 字节；200 条领地约 3.3 KB；500 条约 8.3 KB；1500 条约 25 KB；超过 1 MiB 自动折半裁剪。

## 五、验证情况

1. 离线验证：两端编译通过；PMC3 往返测试（中文名、负坐标、30 万级远坐标、200 字长名截断为 40 字、子领地旗标）全部一致；畸形包 5/5 拒绝。
2. 真实进程验证（本地 Purpur 1.21.11 + Residence 5.1.6.2 + CMILib）：插件正常启用并 hook ok、命令可用、真实 Residence 查询返回正确维度键与微秒级耗时、模拟客户端注册频道后服务端立即下发、抓包解码为 PMC3/26 字节/world=minecraft:overworld/claims=0、心跳重复。
3. 未验证：真实领地数据下的编码、Fabric 客户端模组实际加载与渲染、真实领地渲染对齐误差。

## 六、已知限制

1. 代理多后端（同一域名多个子服）客户端无法区分，ClaimStore 的兜底记录可能串数据；推流数据不受影响。
2. 推送半径上限 32 区块；要全服视角需换方案（例如接 Pl3xMap 网页地图数据源）。
3. 客户端底图是区块平均色，没有地形细节、无缩放档位、无旋转。
4. 聊天兜底依赖 /res show 的文本格式，若服务器改过语言文件可能需要调整解析规则。
5. 子领地会同时显示，视觉上可能重叠在主领地内（描边更细以示区分）。
