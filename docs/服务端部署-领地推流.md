# 服务端部署：PmxxlClaims 领地推流插件

## 1. 它是什么

1. 一个标准 Bukkit 插件（Purpur/Paper/Spigot 通用），只读 Residence 的数据，通过自定义频道 pmxxl:claims 把玩家附近的领地推给装了客户端的玩家。
2. 不做领地判定、不存数据、不改 Residence；不装它服务器一切照旧。

## 2. 安装

1. 前置：Residence 5.1.6.2（含 CMILib）正常在跑。
2. 把 PmxxlClaims-plugin-1.0.0.jar 放进 plugins/，重启服务器（不要 /reload）。
3. 启动日志应出现：PmxxlClaims enabled, Residence hook ok, radius=16

## 3. 配置 plugins/PmxxlClaims/config.yml

1. radius-chunks：推送半径，单位区块，默认 16（即 256 格见方的范围），可调 1 到 64。
2. send-owner：是否把领地拥有者名字一起下发，默认 false（只显示领地名）。
3. 改完执行 /claimsmap reload。

## 4. 命令

1. /claimsmap debug [玩家]：打印该玩家半径内的领地表、查询耗时（微秒）。
2. /claimsmap reload：重载配置。
3. 权限：pmxxlclaims.admin，默认仅 OP。

## 5. 内部行为（便于排查）

1. 触发时机：玩家跨区块立即触发；另有每 2 秒一次的巡检；领地创建/删除/改名/换主/改大小/增删区域时立即重算。
2. 去重：对同一玩家，报文哈希不变就不发，避免刷包。
3. 报文：magic PMC1 + flags + 世界表 + 领地列表（名字/颜色/旗标/每个长方体的两角坐标），超过 1KB 自动 Deflate。
4. 世界标识用 Bukkit World#getKey()（如 minecraft:overworld），与客户端维度 id 对齐。

## 6. 验收

1. /claimsmap debug <玩家> 能看到 claims 数量与耗时。
2. 客户端进服后左上角 claims 数字在 2 秒内变成非 0（当你在领地附近时）。
3. 新建或删除领地，客户端 2 秒内更新。
4. 走出半径后，该领地从小地图消失。

## 7. 失败分支

1. 日志没有 hook ok：Residence 缺失或版本不符，插件会自行 disable。
2. 客户端 claims 不涨但 debug 有数据：客户端没装模组，或频道被其他插件拦截。
3. 包太大导致卡顿：把 radius-chunks 调小（例如 8）。

## 变更记录（2026-10-30 修复轮）

1. 新增心跳：同一玩家 10 秒必发一次，客户端不再误判为无插件。
2. 报文超过 1 MiB 时自动折半裁剪，避免超限异常中断整轮刷新。
3. 半径上限改为 32 区块；ChunkRef 列表缓存复用。
4. 领地变更不再同步刷新，合并到下一 tick。
5. 编译依赖对齐 paper-api 1.21.11。

## 变更记录（2026-10-30 第二轮）

1. 协议升级为 PMC2：单世界字符串 + status 字节，删除 id / Y 轴 / worldIndex 三个无用字段，同等数据体积更小。
2. 编码与压缩移入异步线程，主线程只取快照与发包；每玩家 revision 保证旧结果作废。
3. 查询结果按 (世界,中心区块) 缓存 2 秒，ChunkRef 列表复用；领地变更事件统一失效缓存。
4. 只给注册了 pmxxl:claims 频道的客户端发；Bungee/Velocity 特例用 assume-client-unregistered 显式开启。
5. 半径上限 32，配置越界启动时打 warning。
6. 命令输出统一中文；plugin.yml 补 website；resources filtering 关闭；编译用 release 21。

## 变更记录（2026-10-30 第三轮修复）

1. 协议升 PMC3：去掉恒为 0 的 status 字节；世界字符串上限 512 字节，名字/owner 120 字节，按 UTF-8 字符边界截断。
2. 查询快照 TTL 提到 5 秒（巡检仍 3 秒一次），稳态命中缓存。
3. 大包裁剪改为最多 4 次折半，警告按玩家 60 秒限频。
4. markDirty 与异步编码回调增加 isEnabled 检查，停服后不再调度。
