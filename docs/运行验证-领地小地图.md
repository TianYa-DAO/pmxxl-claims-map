# 运行验证记录：小地图领地（2026-10-30）

## 环境

1. 服务端：本地 Purpur 1.21.11（官方下载），插件 CMILib 1.6.1.2、Residence 5.1.6.2、PmxxlClaims 1.0.0，外加一个自写的探针插件 ClaimApiProbe。
2. 客户端模拟：Node 22 + mineflayer，协议版本 1.21.11，离线模式接入。
3. 控制台：RCON（25575）执行命令。

## 已验证（真实进程、真实插件、真实网络包）

1. 加载：`[领地地图] PmxxlClaims enabled, Residence hook ok, radius=16`，关服时 `Disabling PmxxlClaims v1.0.0` 干净卸载。
2. 命令：RCON 执行 `claimsmap debug TestBot` 返回 `玩家=TestBot 世界=minecraft:overworld / 领地数=0 查询耗时=47us`；`claimsmap reload` 返回 `已重载，半径=16 区块`。
3. 真实 Residence 查询：探针调用 `PmxxlClaims.service().collect(player)`，返回 `world=minecraft:overworld claims=0`，无异常（说明 getResidences/ChunkRef/区域解析这条链路在真插件上可跑）。
4. 频道门控（严格模式）：未注册频道的客户端被跳过；模拟客户端按原版 `minecraft:register` 注册 `pmxxl:claims` 后，服务端开始发送，证明 accepts() 的判断在 Paper 上成立（此前只看 Fabric 源码推断）。
5. 线上报文：抓到的自定义包 channel=`pmxxl:claims`，26 字节，hex `504d433300136d696e6563726166743a6f766572776f726c6400`，按协议解码为 magic=PMC3、flags=0、world=minecraft:overworld、claims=0。
6. 心跳：同一客户端在会话内多次收到同样的帧，符合 10 秒心跳设计。

## 未验证

1. 真实领地数据下的编码（无头环境无法用 Residence 正常建领地：API 静默返回 false，命令需要玩家选区/交互，未继续折腾）。
2. Fabric 客户端的模组加载与 HUD 渲染效果（无图形环境）。
3. 真实领地在小地图上的坐标对齐误差。

## 结论

服务端半边已经用真实进程验证到「帧被客户端正确收到且可解码」；客户端半边只有编译与协议解码的离线证据，必须靠你进游戏实测。
